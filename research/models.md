# Модели: предварительный обзор

Обзор того, какие модели и архитектуры теоретически подходят для проекта и какую роль могут выполнять. 

Источники: официальные репозитории, документация и карточки моделей. 

## Какие задачи различаем

| Задача | Результат | Какие модели рассматриваем |
| --- | --- | --- |
| Выделение опухоли на уже сделанном снимке | Маска очага, из которой можно получить объём и форму | nnU-Net, Swin UNETR, MedSAM2 |
| Получение признаков обследования | Числовое описание изображения для дальнейшего анализа | Радиомика, MedicalNet, CT-CLIP, Merlin, MedSigLIP, BiomedCLIP |
| Анализ изменений между обследованиями | Изменение объёма / признаков, сопоставление очагов | Сегментация, совмещение изображений и сопоставление очагов; временные модели при необходимости |
| Прогноз будущего исхода | Вероятность ответа / прогрессии, будущий объём или время до события | Логистическая регрессия, CatBoost, модели выживаемости, GRU, Transformer |
| Работа с изображениями и медицинским текстом | Ответ на вопрос, структурированные сведения, текстовое описание | MedGemma, Qwen |
| Поиск по базе | Ранжированный список изображений или записей | Модели совместных представлений изображения и текста; текстовые поисковые модели |


## 1. Прогноз по числовым признакам и клиническим данным

На вход можно подавать возраст, подтип опухоли, доступные сведения о терапии, объём очага, характеристики изображения и их изменения к моменту прогноза. Радиомика — извлечение измеримых свойств изображения, а не отдельная прогнозирующая модель; пример инструмента — [PyRadiomics](https://pyradiomics.readthedocs.io/en/latest/).

| Модель / источник | Для какой цели в проекте | Что требуется и какие ограничения | Ресурсы: предварительная оценка |
| --- | --- | --- | --- |
| [Логистическая регрессия](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LogisticRegression.html) | Простой прогноз бинарного исхода: например, pCR или прогрессия за заданный срок | Нужны признаки и метки исхода; регуляризация особенно важна при малой выборке. Выдаваемая вероятность требует проверки калибровки | Обучение и применение на CPU |
| [CatBoost](https://catboost.ai/docs/en/) | Нелинейный прогноз по клиническим, радиомическим и извлечённым нейросетью признакам; классификация или регрессия | Не принимает необработанный 3D-снимок как готовое медицинское исследование; изображения сначала превращаются в признаки | Для небольших таблиц достаточно CPU; GPU необязателен |
| [Cox PH / Random Survival Forest](https://scikit-survival.readthedocs.io/en/stable/user_guide/00-introduction.html) | Оценка риска рецидива / прогрессии и времени до события с учётом неполного наблюдения | Нужны время наблюдения и индикатор события. У Cox есть предположение пропорциональных рисков; применимость зависит от данных | Для нашей предполагаемой численности — CPU |


## 2. Сегментация и извлечение признаков изображений

| Модель / источник | Вход и выход | Возможная роль в проекте | Ограничения и адаптация |
| --- | --- | --- | --- |
| [nnU-Net v2](https://github.com/MIC-DKFZ/nnUNet) | 2D / 3D изображения, в том числе несколько каналов → маска | Выделение опухоли на МРТ / КТ / ПЭТ-КТ; расчёт объёма и признаков по маске | Это автоматически настраиваемая система обучения сегментации, а не универсальные готовые веса для всех опухолей. Нужны подходящие маски или совместимый готовый checkpoint |
| [Swin UNETR, MONAI](https://monai.readthedocs.io/en/1.5.2/networks.html#swinunetr) | Обычно многоканальный 3D-объём → маска | Сравнение трансформерной сегментации с nnU-Net; потенциально использование признаков энкодера | Нужна адаптация к модальности и разметке. Архитектура сама по себе не означает наличие подходящих предобученных весов; память зависит от размера фрагмента объёма |
| [MedSAM2](https://github.com/bowang-lab/MedSAM2) | 3D медицинские изображения и подсказка о цели → маска | Помощь в разметке или сегментация указанного очага | Есть код и готовые веса. Подсказка, например рамка / RECIST-маркер, задаёт цель: модель не следует считать автоматическим детектором всех метастазов. Работа по срезам объёма не означает отслеживание заболевания между визитами |
| [MedicalNet / Med3D, 3D ResNet-18/50](https://github.com/Tencent/MedicalNet) | 3D медицинский объём → пространственные / агрегированные признаки | Компактный энкодер опухолевой области на КТ или МРТ; признаки для классификатора или временной сети | Есть предобученные 3D ResNet. Для нашего исхода нужна новая прогнозирующая часть и, возможно, дообучение; старый репозиторий может потребовать адаптации зависимостей |
| [CT-CLIP](https://github.com/ibrahimethemhamamci/CT-CLIP) | 3D КТ грудной клетки и текст → совместные векторы признаков | Извлечение признаков КТ, поиск по текстовому описанию, классификация с новой прогнозирующей частью | Предобучение на КТ грудной клетки без контраста; перенос на ПЭТ, МРТ и другие области не подтверждён. Авторы указывают A100 80 ГБ для обучения с batch 8; применение возможно на меньших GPU, точный предел уточнять. Указана лицензия CC BY-NC-SA |
| [Merlin](https://github.com/StanfordMIMI/Merlin) | 3D КТ и текст; конкретный выход зависит от варианта | Признаки КТ, поиск изображения по тексту; в проекте есть отдельные варианты генерации описания и прогноза заболеваний | Есть готовые веса. Основная область — КТ живота; перенос на опухолевую динамику требует отдельной модели исхода и оценки. Опубликованный пятилетний прогноз заболеваний не является готовым прогнозом метастазов |
| [MedSigLIP-448](https://huggingface.co/google/medsiglip-448) | 2D изображение и текст → совместные представления / сходство | Медицинский поиск и признаки выбранных срезов или областей | Предобучение включает рентгенограммы, дерматологию, офтальмологию и гистологию. Полный 3D-объём и историю визитов нужно агрегировать отдельно; перенос на КТ / МРТ / ПЭТ исследовательский |
| [BiomedCLIP](https://huggingface.co/microsoft/BiomedCLIP-PubMedBERT_256-vit_base_patch16_224) | 2D изображение и текст → совместные представления / сходство | Альтернатива для поиска и получения признаков срезов | Предобучен на парах изображений и подписей из биомедицинских публикаций; это не специализированный 3D-энкодер онкологических исследований. Потребуется отдельная агрегация срезов |


## 3. Модели истории обследований и объединение модальностей


| Подход / источник | Как используется | Для какой цели | Ограничение |
| --- | --- | --- | --- |
| [GRU](https://pytorch.org/docs/stable/generated/torch.nn.GRU.html) / LSTM | Признаки каждого визита, интервалы между визитами и доступные сведения о лечении → прогноз | Учитывать последовательность изменений, предсказывать исход или будущий объём | Нужен энкодер снимков либо готовые числовые признаки. Обычная GRU не учитывает реальные интервалы автоматически; их нужно явно представлять |
| [Transformer Encoder](https://pytorch.org/docs/stable/generated/torch.nn.TransformerEncoder.html) | Последовательность признаков визитов с кодированием времени → прогноз | Объединять несколько обследований и модальностей | Архитектура требует обучения; малое число пациентов и всего 2–4 визита могут ограничить пользу более сложной модели |
| Совместная модель: энкодер изображения + небольшая MLP / временная сеть | Признаки снимка объединяются с клиническими признаками внутри обучаемой модели | Прямой прогноз pCR, прогрессии или объёма на следующем визите | Это вариант нашей архитектуры, а не отдельная готовая модель. Нужны корректные связи модальностей и исходов; для времени до события — соответствующая функция потерь |
| Ансамбль прогнозов | Объединяются прогнозы моделей, обученных на изображениях и клинических данных | Проверить, дополняют ли модели друг друга | Полезность не гарантирована. Обучение объединяющей модели требует прогнозов вне обучающей выборки; иначе оценка будет завышена |

## Оборудование: что можно предположить

Ориентир — 24 ГБ видеопамяти у прототипа. Оценка осуществимости, а не опубликованный замер на конкретном оборудовании.

| Класс | Предварительная оценка для 24 ГБ |
| --- | --- |
| Табличные модели, модели выживаемости | GPU обычно не нужен |
| 3D ResNet, nnU-Net, Swin UNETR | Есть смысл рассматривать обучение на фрагментах объёма с небольшим batch; возможность зависит от разрешения, каналов и конфигурации сети |
| MedSAM2, MedSigLIP, BiomedCLIP | Кандидаты для локального применения; объём, число срезов и batch определяют фактическую память |
| CT-CLIP, Merlin | Проверять отдельно для конкретного режима; извлечение признаков и полное дообучение имеют разные требования |
| VLM 4B | Около 8 ГБ только на 4 млрд параметров в BF16; остаётся дополнительная память на изображения, контекст и вычисления |
| VLM 9B | Около 18 ГБ только на 9 млрд параметров в BF16; для 24 ГБ запас ограничен, квантование может помочь |
| VLM 27B | Около 54 ГБ только на 27 млрд параметров в BF16. Для 24 ГБ потребуется квантование / выгрузка части вычислений; теоретические 13,5 ГБ при 4 битах не включают служебные данные и память выполнения |

Расчёт весов приблизительный: число параметров × байты на параметр, в десятичных ГБ. 


## Соответствие найденным данным

Возможные сочетания для исследования

| Данные из [обзора датасетов](datasets.md) | Какие варианты имеют смысл теоретически |
| --- | --- |
| QIN-BREAST / ACRIN-FLT-Breast | Признаки опухоли и ПЭТ + клинические данные → регрессия / CatBoost; при истории обследований — изменения признаков или GRU |
| ACRIN-6698 / I-SPY1 / I-SPY2 / NACT-Pilot | Объём, ADC и другие признаки МРТ; MedicalNet либо обучаемый энкодер; объединение с клиническими данными для прогноза ответа или риска события |
| UCSD-BMETS / Burdenko-GBM-Progression | Маски → объём и динамика; nnU-Net / Swin UNETR для сегментации; числовая или временная модель для будущего исхода |
| NLST-New-lesion-LongCT | Сравнение КТ для обнаружения новых очагов; CT-CLIP как возможный источник признаков. Пригодность данных для будущего прогноза пока не установлена |
| QIN-HEADNECK / Anti-PD-1 | Признаки КТ / ПЭТ и их изменения; прогнозирующая часть возможна при наличии соответствующих исходов |

MedGemma и Qwen остаются кандидатами отдельного исследования мультимодального подхода. Прямой прогноз по ним, сочетание энкодера и небольшой прогнозирующей сети, а также радиомика с классической моделью — разные гипотезы, которые пока нельзя ранжировать по качеству на наших данных.

Дополнительные первичные источники: [официальные примеры MedGemma](https://github.com/Google-Health/medgemma/blob/main/notebooks/README.md), [подготовка представления КТ / МРТ в коде MedGemma](https://github.com/Google-Health/medgemma/blob/main/python/serving/predictor.py).
