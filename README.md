# База данных профилактики распространения опухолевого процесса

Исследовательский проект по созданию базы лонгитюдных медицинских данных и прототипа прогнозирования распространения опухоли. Система должна использовать историю обследований пациента и доступные сведения о лечении, чтобы оценивать появление новых опухолевых очагов и динамику заболевания.

**Статус:** выполнены обзор данных, аудит Duke-Breast-Cancer-MRI и сравнение пяти survival-моделей на CPU на 20 общих пятиблочных разбиениях. Рабочая когорта — 674 пациента / 47 отдалённых событий. Средний C-index: Cox по возрасту — 0,543, по объёму опухоли МРТ — 0,693, по возрасту и объёму — 0,686; Random Survival Forest — 0,619, survival-бустинг — 0,662. В проверенных фиксированных конфигурациях лес и бустинг не улучшили обычный C-index относительно Cox по двум признакам ни на одном разбиении. Доверительные интервалы, абсолютный риск и внешняя проверка ещё не выполнены.

Обзоры: [датасеты](research/datasets.md), [модели](research/models.md). Текущая работа: [аудит Duke](reports/duke/audit.md), [проверка первичных источников](research/duke-source-review.md), [протокол эксперимента](research/duke-protocol.md), [первые результаты и ограничения](reports/duke/baseline.md), [устойчивость на повторных разбиениях](reports/duke/stability.md), [сравнение пяти методов](reports/duke/model_comparison.md).

## Цель

Сравнить мультимодальные модели и ансамбли моделей на выбранном наборе данных и проверить возможность создания прототипа с измеримым качеством и умеренными требованиями к оборудованию.

Конкретный прогнозируемый показатель и горизонт прогноза будут определены после изучения доступных данных. Обнаружение изменений между уже выполненными обследованиями и прогноз будущих изменений оцениваются как разные задачи.

## Основные направления

- **Данные:** подбор открытого датасета, связывание обследований по пациентам и организация изображений в хронологическом порядке.
- **Прогнозирование:** сравнение отдельных мультимодальных моделей и ансамблей на общей выборке по единым правилам.
- **Прототип:** загрузка подготовленных данных, выполнение прогноза и сопоставление результата с фактическим исходом.
- **Поиск по базе:** дополнительный компонент для поиска медицинских изображений и связанных записей через естественный язык.

## Требования к данным

Приоритет — рак молочной железы. Другой вид рака допустим при наличии более подходящих данных и обосновании выбора.

| Параметр | Что требуется проверить |
| --- | --- |
| Повторные обследования | Несколько временных точек для одних и тех же пациентов |
| Временная структура | Идентификаторы пациентов, даты и порядок обследований |
| Изображения | Модальность и формат файлов; предварительно рассматриваются КТ и ПЭТ-КТ |
| Лечение | Доступность сведений о терапии |
| Исходы | Разметка или последующее обследование для проверки прогноза |
| Доступ | Условия использования и порядок получения данных |
| Объём | Желательно около 250 ГБ, ориентировочный предел — 1 ТБ |

Сравнение сценариев «с лечением / без лечения» остаётся исследовательским вопросом. Его постановка зависит от данных и требует отдельного обоснования.

## Модели и оценка

Планируется сравнить:

- простое базовое решение;
- ансамбль трансформеров и классических моделей машинного обучения;
- отдельную мультимодальную модель.

Qwen 27b рассматривается как кандидат. Точное название, версия, размер и поддержка изображений требуют уточнения. Ollama рассматривается как средство локального запуска моделей.

Для экспериментов необходимо определить целевой показатель, горизонт прогноза и соответствующие метрики. Разделение данных следует выполнять по пациентам, исключая использование будущих обследований во входных данных. Помимо качества, сравниваются время выполнения и потребление видеопамяти.

## Запуск

Для аудита и первых моделей достаточно CPU. Единый способ установки и запуска проекта — [uv](https://docs.astral.sh/uv/). Версия Python 3.12 указана в [.python-version](.python-version), прямые зависимости — в [pyproject.toml](pyproject.toml), точные версии и хеши пакетов — в [uv.lock](uv.lock).

Все команды выполняются из корня проекта. Подготовка общего окружения для аудита, моделей и тестов:

```bash
uv sync --locked
uv run --locked scripts/download_duke.py
uv run --locked scripts/audit_duke.py
```

Опционально скачать две серии одного пациента (около 50 МБ ZIP суммарно) и проверить чтение DICOM, пиксельные данные и геометрию:

```bash
uv run --locked scripts/download_duke.py --sample-mri
uv run --locked scripts/check_duke_mri.py
uv run --locked scripts/audit_duke.py
```

Проверки правил времён, исходов и цензурирования:

```bash
uv run --locked python -m unittest discover -s scripts -p 'test_duke_audit.py' -v
```

Подготовка таблиц и запуск первых моделей в том же окружении:

```bash
uv run --locked scripts/prepare_duke_baseline.py
uv run --locked scripts/run_duke_baseline.py
uv run --locked scripts/check_duke_stability.py
uv run --locked scripts/compare_duke_models.py
uv run --locked python -m unittest discover -s scripts -p 'test_*.py' -v
```

До подготовки таблиц скачайте исходные XLSX командой `scripts/download_duke.py` из раздела аудита. Подготовка пересчитывает отбор по исходным файлам; отдельный запуск аудита для неё не обязателен.

`check_duke_stability.py` выполняет 20 заранее заданных разбиений для обеих моделей и двух сценариев, сохраняя первый эксперимент. Отчёт и полные метрики — `reports/duke/stability.md` и `stability_results.json`; блоки и индивидуальные прогнозы — `data/derived/duke/baseline/stability_folds.csv` и `stability_scores.csv`. Диапазоны метрик между повторениями не являются доверительными интервалами.

`compare_duke_models.py` сравнивает Cox по возрасту, объёму и обоим признакам, Random Survival Forest и survival-бустинг на тех же 20 разбиениях и двух сценариях. Параметры зафиксированы без подбора; каждый метод использует только разрешённые признаки. Отчёт и полные настройки — `reports/duke/model_comparison.md` и `model_comparison_results.json`; индивидуальные баллы и блоки — `data/derived/duke/baseline/comparison_scores.csv` и `comparison_folds.csv`.

В этом сравнении Cox только по объёму немного выше Cox по возрасту и объёму: средняя парная разность C-index +0,007, положительна на 18 из 20 разбиений. Самостоятельной пользы возраста при уже известном объёме пока не показано. Проверенные лес и бустинг имеют меньший средний C-index; это вывод о конкретных настройках и двух входах, а не о предельном качестве этих методов. Следующий эксперимент — расширение информации об опухоли с защитой от переобучения при отборе признаков.

`uv sync --locked` устанавливает зависимости в общее окружение `.venv`, а `uv run --locked` запускает команды в нём. Активация окружения вручную не требуется. Первый запуск может загрузить Python и зависимости. Python 3.12 выбран для совместимости пакетов моделей; на некоторых платформах для сборки `ecos` может потребоваться компилятор.

Для добавления зависимостей используйте `uv add имя-пакета`, для обновления зафиксированных версий — `uv lock --upgrade`, затем `uv sync --locked` и тесты. Изменения `pyproject.toml` и `uv.lock` сохраняются в Git вместе.

[Снимок окружения первого эксперимента](reports/duke/requirements-first-run.txt) на Linux / Python 3.12.15 хранится вместе с отчётом как историческая запись. Рабочее окружение проекта определяется `pyproject.toml` и `uv.lock`.

Исходные данные и таблицы по пациентам сохраняются в игнорируемой Git папке `data/`. В `data/derived/duke/baseline/` отдельно лежат только разрешённые признаки, исходы, номера блоков и прогнозные баллы для пациентов, не участвовавших в обучении соответствующей модели. SHA-256 подготовленных файлов проверяются перед запуском расчёта. Агрегированные результаты и версии — в `reports/duke/baseline.md`, `baseline_inputs.json` и `baseline_results.json`. Команды пока выполняют кросс-валидацию; сохранённая модель для применения к новому пациенту не создаётся.
