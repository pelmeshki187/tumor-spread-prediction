# База данных профилактики распространения опухолевого процесса

Исследовательский проект по созданию базы лонгитюдных медицинских данных и прототипа прогнозирования распространения опухоли. Система должна использовать историю обследований пациента и доступные сведения о лечении, чтобы оценивать появление новых опухолевых очагов и динамику заболевания.

**Статус:** выполнены обзор данных, аудит Duke-Breast-Cancer-MRI и первое сравнение двух Cox-моделей на CPU. Рабочая когорта — 674 пациента / 47 отдалённых событий; пять общих блоков валидации. C-index: возраст — 0,539, возраст + объём опухоли МРТ — 0,692. Это предварительная оценка ранжирования; абсолютный риск и внешняя проверка ещё не выполнены.

Обзоры: [датасеты](research/datasets.md), [модели](research/models.md). Текущая работа: [аудит Duke](reports/duke/audit.md), [проверка первичных источников](research/duke-source-review.md), [протокол первого эксперимента](research/duke-protocol.md), [первые результаты и ограничения](reports/duke/baseline.md).

## Цель

Сравнить мультимодальные модели и ансамбли моделей на выбранном наборе данных и проверить возможность создания прототипа с измеримым качеством и умеренными требованиями к оборудованию.

Конкретный прогнозируемый показатель и горизонт прогноза будут определены после изучения доступных данных. Обнаружение изменений между уже выполненными обследованиями и прогноз будущих изменений оцениваются как разные задачи.

## Основные направления

- **Данные:** подбор открытого датасета, связывание обследований по пациентам и организация изображений в хронологическом порядке.
- **Прогнозирование:** сравнение отдельных мультимодальных моделей и ансамблей на общей выборке по единым правилам.
- **Прототип:** загрузка подготовленных данных, выполнение прогноза и сопоставление результата с фактическим исходом.
- **Поиск по базе:** дополнительный компонент для поиска медицинских изображений и связанных записей через естественный язык.

## Требования к данным

Приоритет — рак молочной железы. Другой вид рака допустим при наличии более подходящих данных и обосновании выбора.

| Параметр | Что требуется проверить |
| --- | --- |
| Повторные обследования | Несколько временных точек для одних и тех же пациентов |
| Временная структура | Идентификаторы пациентов, даты и порядок обследований |
| Изображения | Модальность и формат файлов; предварительно рассматриваются КТ и ПЭТ-КТ |
| Лечение | Доступность сведений о терапии |
| Исходы | Разметка или последующее обследование для проверки прогноза |
| Доступ | Условия использования и порядок получения данных |
| Объём | Желательно около 250 ГБ, ориентировочный предел — 1 ТБ |

Сравнение сценариев «с лечением / без лечения» остаётся исследовательским вопросом. Его постановка зависит от данных и требует отдельного обоснования.

## Модели и оценка

Планируется сравнить:

- простое базовое решение;
- ансамбль трансформеров и классических моделей машинного обучения;
- отдельную мультимодальную модель.

Qwen 27b рассматривается как кандидат. Точное название, версия, размер и поддержка изображений требуют уточнения. Ollama рассматривается как средство локального запуска моделей.

Для экспериментов необходимо определить целевой показатель, горизонт прогноза и соответствующие метрики. Разделение данных следует выполнять по пациентам, исключая использование будущих обследований во входных данных. Помимо качества, сравниваются время выполнения и потребление видеопамяти.

## Запуск

Для текущего аудита достаточно CPU и Python 3.11+. Команды из корня проекта, окружение создаётся через [uv](https://docs.astral.sh/uv/):

```bash
uv venv .venv
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python scripts/download_duke.py
.venv/bin/python scripts/audit_duke.py
```

Опционально скачать две серии одного пациента (около 50 МБ ZIP суммарно) и проверить чтение DICOM, пиксельные данные и геометрию:

```bash
.venv/bin/python scripts/download_duke.py --sample-mri
.venv/bin/python scripts/check_duke_mri.py
.venv/bin/python scripts/audit_duke.py
```

Проверки правил времён, исходов и цензурирования:

```bash
.venv/bin/python -m unittest discover -s scripts -p 'test_duke_audit.py' -v
```

Для воспроизведения первых моделей используйте отдельное окружение Python 3.12. Оно проверено с готовыми бинарными пакетами на Linux; зависимость `ecos` не установилась без компилятора на Python 3.13/3.14:

```bash
uv venv --python 3.12 .venv-baseline
uv pip install --python .venv-baseline/bin/python --only-binary :all: -r requirements-baseline.lock.txt
.venv-baseline/bin/python scripts/prepare_duke_baseline.py
.venv-baseline/bin/python scripts/run_duke_baseline.py
.venv-baseline/bin/python -m unittest discover -s scripts -p 'test_*.py' -v
```

До подготовки таблиц скачайте исходные XLSX командой `scripts/download_duke.py` из раздела аудита. Подготовка пересчитывает отбор по исходным файлам; отдельный запуск аудита для неё не обязателен. Список прямых зависимостей моделей — `requirements-baseline.txt`, точные версии первого запуска — `requirements-baseline.lock.txt`.

Исходные данные и таблицы по пациентам сохраняются в игнорируемой Git папке `data/`. В `data/derived/duke/baseline/` отдельно лежат только разрешённые признаки, исходы, номера блоков и прогнозные баллы для пациентов, не участвовавших в обучении соответствующей модели. SHA-256 подготовленных файлов проверяются перед запуском расчёта. Агрегированные результаты и версии — в `reports/duke/baseline.md`, `baseline_inputs.json` и `baseline_results.json`. Команды пока выполняют кросс-валидацию; сохранённая модель для применения к новому пациенту не создаётся.
